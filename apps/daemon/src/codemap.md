# apps/daemon/src/

## Responsibility

Implements the local daemon's application layer: process startup, production dependency composition, daemon lifecycle, RPC result projection, Bun Unix-socket transport, and signal-driven shutdown.

## Design / patterns

- `main.ts` is the direct Bun process entry point; it contains root selection, runtime startup, signal registration, lifetime waiting, and bounded rendering of structured startup failures to stable process exits. The CLI launches it detached; running the executable directly enters the internal `runForegroundMain()` debug path, and no public foreground `serve` command exists.
- `runtime.ts` is the composition root. Its injectable hooks isolate startup/lifecycle tests while `productionServices()` wires logger, Realm/Source/Auth, Action describe/run, export, search/retrieval/thread services, one shared secret vault/backend manager, and `SyncApplicationService`; startup separately adapts the exact loaded Extension documentation projection into a read-only core documentation service.
- `application.ts` implements the contract-derived nested `DaemonRpcApplication` tree; it translates public core results into bounded RPC DTOs, preserves trusted auth/sync/validation/lookup taxonomy separately from public codes, and never exposes raw provider, storage, or diagnostic text. It may forward only SDK-tagged public sync messages that core has structurally validated and marked public; ordinary Error and internal provider text remain redacted. Streamed sync hands events to the transport through a one-item rendezvous and retains activity until terminal consumption, return, throw, cancellation, disconnect, or shutdown settles exactly once; any abort of the internal request controller, including `beginStopping()`, closes the rendezvous so a producer parked on an unconsumed event is released before the guarded once-only finalizer runs. Known defect: on pinned Bun 1.3.14 the `Bun.serve` stream transport reads the iterator without waiting for a stalled client, so the daemon buffers the operation instead of applying producer backpressure. The business request tracker owns idle lifetime on an injected monotonic clock: it closes idle daemons without interrupting admitted business work, and health probes (which back `daemon status`) never touch the deadline.
- `registry.describe` projects the loaded registry with core `describeRegistry`; `extension.list` projects loaded identities plus startup-captured provenance, `projectDirectExtensionRecord` inventory, and host-safe diagnostics. Both use ordinary tracked business admission and strict RPC schemas; only named business Extension locations cross this read boundary, never executable definitions or runtime roots.
- Authenticated Source creation derives the explicit Provider/access authorization binding from the loaded Adapter before matching persisted Grants; the Adapter definition itself is never mistaken for an auth contract.
- The secret-access barrier serializes ordinary shared work against backend switching, while the one-shot `account.respond` rendezvous bypasses that queue so it can release an authorization already holding shared access without deadlock.
- `transfer.ts` owns the bounded in-memory, single-use, expiring byte-ticket registry. `transport.ts` keeps Bun-specific `Bun.serve`, the exact owner-private transfer route (which applies `rpcCompatibilityFailure()` and answers HTTP `409` with the declared failure before consuming a ticket), and oRPC `RPCHandler` adaptation outside RPC contracts and core. `signals.ts` adapts process signals to `RunningDaemon.close()`.

## Data & control flow

1. `startDaemon()` resolves canonical roots and endpoint identity, obtains exclusive retained lifecycle/database leases, safely projects database ownership conflicts, writes `starting` discovery metadata, reads unified direct and Catalog-curated installation records from `DirectExtensionStore`, opens/migrates the database, reads persisted local OAuth App identities, then loads installed Extensions offline with complete-registry collision validation and composes services. Invalid records contribute bounded startup diagnostics without blocking unrelated roots.
2. The runtime constructs `DaemonApplication`, owner-validates that any stale endpoint is a same-user single-link Unix socket before removal, binds `bindDaemonTransport()`, marks readiness, and writes `ready` metadata last. Unsafe regular-file or symlink endpoints fail closed before bind.
3. The transport validates protocol/runtime headers and size-bounds the serialized runtime identity before routing `/rpc` requests with request ID and client protocol/runtime metadata; oRPC supplies the native request signal to the contract implementation separately.
4. `health` reports lifecycle state; business requests rejected during startup or shutdown receive lifecycle-specific bounded diagnostics. Every business family (registry, extension, Realm, Source, status, sync, search, resource, thread, export, Artifact, Action, Account, OAuth App, secrets, and documentation) delegates through daemon-owned services. Secret switching takes an exclusive application barrier against all other business work so the core manager's copy/verify/commit/cleanup transaction and the daemon's mutable write-vault selection change atomically; safe status and ordinary operations share the barrier concurrently. RPC exposes only aggregate counts and a fixed cleanup warning, and maps backend failures to bounded messages without references or values. Readiness arms the fixed five-minute idle deadline only when no business request is tracked; every admission disarms it, the final overlapping settlement (including stream iterator finalization) rearms one full interval, and health/shutdown never touch it. Source `status.get` is ordinary tracked business work. Expiry rechecks state and the monotonic deadline before calling `beginStopping()`. Sync remains one tracked business request while its strict count-only events stream; iterator return, disconnect, request cancellation, and shutdown abort and settle the producer. Documentation inventory/search omit content, exact image retrieval uses bounded Base64, and no source path or executable definition crosses RPC. Search and Action procedures resolve Source references before core execution; provider warnings and results cross only bounded projections. The contract implementation forwards native cancellation into application operations. Explicit or idle `shutdown` starts the same admission closure and drain/finalization.
5. Finalization waits for active requests, closes database/listener, conditionally cleans matching discovery metadata and endpoint, and releases database then lifecycle leases. Startup failure rolls the same acquired state back.

## Integration points

- `index.ts` exposes the reusable application, runtime, signal, and transport APIs.
- `main.ts` is compiled/executed directly as the daemon sibling. Compiled suites under `e2e/` run on Darwin and Linux: `compiled-daemon` covers background start, concurrent convergence, idempotent stop, SIGKILL recovery, alias contention, and no direct fallback; `compiled-lease` covers packaged exclusive election, crash release, never-unlinked lease files, and alias ownership against direct openers; `compiled-daemon-ownership` drives the stateful command inventory through the daemon; `compiled-extension-registry` covers launch-directory-independent Extension paths and restart-only registry changes; `compiled-extension` loads a relocated external Extension; `compiled-idle-exit` uses the internal `CTXINDEX_TEST_DAEMON_IDLE_TIMEOUT_MS` shortening control to prove a packaged daemon exits despite `daemon status` polling and restarts on demand.
- Depends on public `@ctxindex/core/*`, `@ctxindex/local-daemon`, `@ctxindex/rpc`, `@ctxindex/official`, and `@orpc/server` seams only.
